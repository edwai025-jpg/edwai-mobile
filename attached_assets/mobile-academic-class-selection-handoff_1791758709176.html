Mobile implementation handoff

EDUwAI Academic Class Selection

Source-based guide to the existing web behavior: default to the profile class when it is available, keep returned same-board choices selectable, and refresh subjects/books after a class change.

Important API limitation for switching grades

The web UI keeps other returned classes selectable and the class/subject endpoints can return processed content across the student's board. But GET /api/documents also filters non-institute users to their profile current_user.class_id. A different requested class can therefore return no books.

This means review of another grade is not yet fully supported by the existing document-list API. Mobile must not bypass this by changing board IDs or using another endpoint. A backend access-rule change is needed before cross-class book selection can fully work; this handoff includes no backend change.

Scope and ownership

  • Recreate the class selector/defaulting behavior in mobile and use the existing authenticated EDUwAI client.
  • Use the authenticated profile's class_id and GET /api/student/available-classes.
  • Let the backend own board/org access, subject availability, document access, and processed status.
  • This is academic/Phase 1 only. It does not change Phase 2 uploads, YouTube mode, profile creation, or class assignment.
  • Keep the question interface hidden until a source/document is selected.

Web UI rule

Select Your Source appears in academic mode when board restrictions allow it:

(!boardStatus?.is_restricted ||
  boardStatus?.processing_status === 'completed') &&
!useOwnBook

The selector is a three-step flow: Class → Subject → Source. Keep the class selector available after defaulting.

Defaulting and fallback

Wait for a non-empty available-class list and the student's profile class ID. Match IDs by string value, so a numeric API ID matches a string profile ID.

  • If the profile class is in the returned list, select it.
  • If a board student's profile class is absent, leave the selector empty. Do not choose an unrelated grade automatically.
  • Apply this only as the initial default; a deliberate selection must not be overwritten.
  • Institute students are identified by org_role === 'student' plus org_id. Prefer their assigned class, or retain the existing fallback to the first org-returned class. Do not mix org and board lists.
const profileClass = classes.find(
  item => String(item.id) === String(user.class_id)
);

On class change

  1. Store the selected class ID.
  2. Immediately clear the current subject, subject list, book list, and selected book.
  3. Fetch subjects for the new class, then fetch books for the selected class and subject.

Subject, source, and question UI

  • Auto-select a subject only if exactly one is returned. With multiple or zero subjects, no subject is selected automatically.
  • Load documents after class and subject are selected. Auto-select only when exactly one document is returned; otherwise the student chooses.
  • Disable the Source selector when no current documents are available.
  • The academic question area is gated by a selected document. Class or subject selection alone does not show it.

Existing authenticated API sequence

Use the mobile app's configured EDUwAI origin and current bearer-token client. These paths are relative to the API origin; include /api exactly once if the client's base URL does not already include it. Do not send a user ID.

1. Available classes

GET /api/student/available-classes
Authorization: Bearer <existing access token>

Returns an array of { id, name } objects. The board-student branch returns distinct classes with processed, public documents on the authenticated user's board. The institute-student branch returns processed documents from that user's organization. No client-supplied board ID is accepted.

[
  { "id": 9, "name": "Class 9" },
  { "id": 10, "name": "Class 10" },
  { "id": 11, "name": "Class 11" }
]

2. Available subjects

GET /api/student/available-subjects?class_id=9
Authorization: Bearer <existing access token>
["Mathematics", "Science"]

Results are based on processed documents scoped to the authenticated user's board or organization, then narrowed by class_id.

3. Documents/books

GET /api/documents?class_id=9&subject=Mathematics
Authorization: Bearer <existing access token>

The response is a list of processed document objects. The selector needs at least id and title; the API also returns board, class, and medium fields.

Do not promise cross-grade document loading yet.

For non-institute users, /api/documents applies the profile's current_user.class_id as an additional filter, as well as the requested class and any profile medium. A request for a different class can return an empty list. Keep the same authenticated behavior; do not implement a client-side access workaround.

Mobile acceptance checklist

  • Load classes from the existing authenticated endpoint.
  • Wait for the profile class ID and select it only if present in the returned list.
  • When the profile class is unavailable, leave board students unselected rather than choosing another grade.
  • Keep all returned classes selectable and preserve institute/org scope.
  • On class change, immediately clear downstream selections and reload subjects/books.
  • Preserve single-result auto-selection for one subject or one book.
  • Do not show the question interface until a source is selected.
  • Do not bypass the current `/api/documents` profile-class restriction; cross-grade book loading needs a backend change.
