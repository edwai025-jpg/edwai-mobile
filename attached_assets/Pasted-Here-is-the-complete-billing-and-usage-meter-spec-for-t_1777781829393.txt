Part 1 — The One API Call You Need (Usage Meter)

Everything the banner widget needs comes from a single endpoint. Call it once after login, then refresh it after every question is answered (since the count increments then).

GET /api/billing/usage/me
Authorization: Bearer <token>

Full Response Shape

{
  "user_id": 42,
  "tier_slug": "free",
  "tier_name": "Free",
  "status": "free",
  "questions_used": 12,
  "question_limit": 50,
  "percent_used": 24.0,
  "period_start": "2026-05-03T00:00:00",
  "period_end": "2026-06-03T00:00:00",
  "days_remaining": 31,
  "grace_period_ends": null,
  "warning_80_sent": false,
  "limit_reached_sent": false,
  "autopay_enabled": false
}

Field Reference
Field	Type	Description
tier_slug	string	"free" · "tier1" · "tier2" · "tier3"
tier_name	string	Display name, e.g. "Free", "Basic", "Pro"
status	string	See Status Values table below
questions_used	int	Questions asked in this billing period
question_limit	int	Maximum allowed (50 for free / past_due)
percent_used	float	0.0 – 100.0, already rounded to 1 decimal
period_end	ISO datetime	When the current period resets (for the "↺ 2 Jun" label)
days_remaining	int	Days until period_end, minimum 0
grace_period_ends	ISO datetime or null	Only set when status === "grace_period"
autopay_enabled	bool	Whether auto-renew is on
Status Values
status	Meaning	Access level
"free"	Free tier, normal	50 Q/month
"active"	Paid, current	Full tier limit
"grace_period"	Payment failed, 7-day window	Full access still (no gate)
"past_due"	Grace expired, downgraded	Capped back to 50 Q/month
"cancelled"	Manually cancelled	Access until period_end

Part 3 — Three Status Banners

These appear as a full-width bar below the app header (above main content). Show at most one at a time, checked in this priority order: grace_period → past_due → payhall.
Banner A — Grace Period (payment failed, still has access)

Condition: usage.status === "grace_period"

Background: #f59e0b  (amber-500)
Text color:  #1c1a00  (amber-950)

Left text:

⚠️ Your last payment failed. Update your payment method to avoid losing access.
   ({N} days remaining)

where N = Math.max(0, ceil((grace_period_ends - now) / 86400000))

Right button:

    If usage.payment_method_update_url is non-null → open that URL in external browser, label: "Update Card →"
    If null → open Upgrade modal with reason "grace", label: "Resolve Now →"

Banner B — Past Due (downgraded)

Condition: usage.status === "past_due"

Background: #dc2626  (red-600)
Text color:  #ffffff

Left text:

⛔ Your account has been downgraded. Questions are now limited. Renew to restore full access.

Right button: "Restore Access →" → opens Upgrade modal with reason "past_due"
Banner C — Payhall (just hit the limit this session)

Condition: percent_used >= 100 (detected locally after each question answer)

This is an in-page notification card (not a full-width banner), shown above the question input. It can be dismissed by the user.
Mode	Background	Border	Text
Dark	rgba(245,158,11,0.10)	rgba(245,158,11,0.30)	#fbbf24 (amber-400)
Light	#fffbeb (amber-50)	#d97706 (amber-300)	#92400e (amber-800)

Buttons:

    "Upgrade Now" → opens Upgrade modal with reason "limit_exceeded"

When to trigger: After each question answer arrives (after streaming done event), check if the returned usage crosses 100%. Do not re-show if the user has already dismissed it this session.
Part 4 — Subscription Detail (Profile Screen)

For the Profile / Account screen, use this richer endpoint:

GET /api/billing/subscription/me
Authorization: Bearer <token>

Response adds:

{
  "tier_slug": "tier1",
  "tier_name": "Basic",
  "status": "active",
  "billing_period": "monthly",
  "period_start": "2026-05-01T00:00:00",
  "period_end": "2026-06-01T00:00:00",
  "grace_period_ends": null,
  "razorpay_subscription_id": "sub_abc123",
  "razorpay_payment_method_url": "https://razorpay.com/...",
  "questions_used": 12,
  "question_limit": 500,
  "autopay_enabled": true
}

Additional fields vs /usage/me:

    billing_period — "monthly" or "yearly"
    razorpay_subscription_id — for reference
    razorpay_payment_method_url — deep link to update card in Razorpay (may be null)

Part 6 — Toggle Autopay

PATCH /api/billing/autopay
Authorization: Bearer <token>

No request body. Toggles the current state.

Response:

{ "success": true, "autopay_enabled": false }

Errors:

    400 if user is on free tier ("Autopay is only available on paid plans")

After a successful toggle, update your local usage object's autopay_enabled field. No need to re-fetch the full usage.

Disable the toggle UI (grey it out + show tooltip "Available on paid plans") when tier_slug === "free" or tier_slug is null.
Part 7 — Payment Limit Enforcement (How Questions Are Gated)

The backend uses a "freemium payhall" model — answer first, gate next. That means:

    The 50th question is answered normally
    The usage count increments to 50 (100%)
    The 51st question attempt gets a 402 Payment Required response:

{
  "detail": "upgrade_required",
  "tiers": [
    {
      "slug": "tier1",
      "name": "Basic",
      "question_limit": 500,
      "monthly_price_inr": 99,
      "yearly_price_inr": 999
    }
  ]
}

On receiving HTTP 402 from any query endpoint, show the Upgrade modal with the tiers array from the response body.
Part 8 — Refresh Strategy
When	Action
App launch / login	Call GET /api/billing/usage/me, cache result
After each question answer	Re-call GET /api/billing/usage/me to update count
Receive HTTP 402	Show Upgrade modal, do not update usage cache
After successful payment verification	Re-call GET /api/billing/usage/me to reflect new tier
Pull-to-refresh on Profile screen	Re-call GET /api/billing/subscription/me

Cache the result in memory for the session. Store billing_usage in local storage as backup so the widget renders immediately on next app open before the API call returns.
