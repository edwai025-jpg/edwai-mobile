Use the mobile app’s existing authenticated EDUwAI API client.

The web production configuration currently points to:

https://api.eduwai.in/api
This address was extracted from src-frontend/config.js; production reachability was not tested in this extraction.

All routes below require the existing bearer access token:

Authorization: Bearer <access token>

Do not connect the mobile build to Replit’s development /api proxy, and do not embed AI-provider credentials in the app.

Preserve this context for each completed answer
original question
completed answer text
answer language
user medium_name
book title, if available
first source page number, if available
answer identity/version for rejecting stale results
Freeze this context per answer. Editing the question input afterward must not change which question is sent for flashcards or reports.

4. Read Aloud
API
POST /api/tts
{
  "text": "Plain-text version of the completed answer",
  "language_code": "en-IN"
}
Response: binary audio, not JSON and not an audio URL.

Possible content types:

audio/mpeg
audio/wav
Read the actual Content-Type; do not assume one file format.

Button states
Read Aloud → Loading… → Pause
Pause → Resume
Resume → Pause
Playback ends → Read Aloud
While playing or paused, show an adjacent ■ Stop button. Pause, resume and stop are local player operations—no API calls.

Disable Read Aloud while:

Its audio is loading.
Tutor Explanation is generating.
Tutor Explanation is playing.
Existing backend limits
The current implementation reads only an initial portion of long text:

GCP primary path: first 400 words.
GCP fallback: first 120 words.
Development path: first 80 words.
Do not promise that the entire long answer will be spoken. These are backend limits, not native UI failures.

Errors include 400 for empty text and 503 for unavailable TTS. Native should show an error/retry state; the existing web hook silently resets on failure.

Sources: useTextToSpeech.js, main.py:6362–6444

5. Tutor Explanation and voice quota
This generates a new teacher-style explanation, rather than reading the original answer verbatim.

Fetch quota
GET /api/student/explain-quota
Example structure:

{
  "allowed": true,
  "used": 0,
  "limit": 10,
  "remaining": 10
}
The screenshot’s 10/10 means remaining / limit. It is not a hardcoded allowance and is separate from the main question quota.

Generate explanation
POST /api/explain
{
  "text": "Plain-text version of the completed answer",
  "language": "english"
}
Notice the difference:

Read Aloud: language_code: "en-IN"
Tutor Explanation: language: "english"
Response body: binary MP3 or WAV audio.

Response header:

X-Explain-Text: <base64-encoded UTF-8 explanation>
Base64-decode the header into bytes, then decode those bytes as UTF-8. Display:

Explanation: [decoded transcript]
The transcript appears above the action bar. Audio may cover only its initial portion: the primary GCP path caps spoken text at 4,500 UTF-8 bytes; fallback/development paths use shorter excerpts.

Button states
Tutor Explanation → Generating… → Pause
Pause → Resume
Playback ends or Stop → Play again
Show an adjacent ■ Stop while playing or paused.
Pause/resume/replay reuse downloaded audio.
Play again must not call /explain again or consume another allowance.
Disable generation while Read Aloud is loading, playing or paused.
Voice quota becomes amber when remaining is 1–3.
At zero remaining, replace the compound control with Voice limit reached.
Quota errors
Exhaustion returns 429 with JSON:

{
  "detail": {
    "quota_exceeded": true,
    "explains_used": 10,
    "explain_limit": 10,
    "message": "..."
  }
}
Because success is binary, the client must still decode error bytes as JSON when a non-success response arrives.

Refresh quota after successful generation, a quota error, and app resume. Do not rely exclusively on a local decrement.

Sources: AnswerRenderer.jsx, main.py:6462–6631,9780–9788

6. Quiz Me
Placement and behaviour
Tapping Quiz Me opens a modal and immediately requests questions. Native may use a full-screen modal or sheet, with safe-area padding and scrollable content.

API
POST /api/mcq
{
  "text": "Plain-text version of the completed answer",
  "language": "english"
}
Example response structure, with fictional content:

{
  "questions": [
    {
      "question": "Example question?",
      "options": ["Option A", "Option B", "Option C", "Option D"],
      "correct": 0,
      "difficulty": "easy",
      "explanation": "Why Option A is correct."
    }
  ]
}
correct is a zero-based option index, not an option letter.

The backend requests a variable number of questions based on input length:

Answer word count	Requested questions
Under 100	4
100–249	6
250–449	8
450 or more	10
Render the actual returned array. Do not hardcode six questions.

Local quiz operations
These do not call the backend:

Select an option.
Check Answer.
Reveal the correct answer/explanation.
Calculate the score.
Submit the quiz; unanswered items count as incorrect.
Regenerate/Retake requests /mcq again and resets selections and score. The current route has no dedicated quiz quota.

Each quiz question also supports Report Issue through the same report endpoint described below.

Validation: the backend checks that the generated result is a nonempty array, but does not fully validate each question. Native should validate option arrays, correct-index bounds and required fields before rendering.

Sources: MCQModal.jsx, main.py:6634–6752

7. Flashcards
API
POST /api/flashcards
{
  "question": "Original question for this answer",
  "answer": "Completed answer, retaining its original text"
}
Unlike TTS and quiz requests, the web sends the original answer, not the stripped speech version.

Response structure:

{
  "flashcards": [
    {
      "front": "Recall question",
      "back": "Answer",
      "type": "concept"
    }
  ],
  "count": 1
}
Supported types:

definition
concept
process
fact
diagram
diagram is a card category, not a guaranteed image URL.

Display and operations
Opens an inline Flashcard Practice panel below the button row.
Tap a card to flip front/back.
Previous/next navigation is local.
Mark mastered/unmastered is local.
Progress and mastered count are local.
Collapse/expand reuses the current deck.
Regenerate calls /flashcards again and resets practice progress.
There is no mastery-save endpoint in this component.

Decks cover one answer, not the whole textbook. The service uses at most the first 15,000 answer characters and returns at most 10 cards.

Timing and errors
The route has a 65-second server generation timeout. Allow a client timeout of approximately 90 seconds, subject to the actual production gateway’s limits; do not impose a 20–30-second timeout.

Handle:

422: invalid input or validation failure.
502: generation failed.
504: generation timed out.
Prevent duplicate generation taps. Reusing an existing deck on reopening is a native efficiency recommendation; the current top-level web Flashcards button triggers regeneration on repeated clicks.

Sources: FlashcardSection.jsx, flashcard_service.py, main.py:7537–7594

8. Report Issue
Tapping Report Issue only opens the form. No request is sent until Submit Report.

The web form expands inline below the action bar.

Issue values
Send the exact ID, not its display label:

Display label	API value
Incorrect answer	incorrect
Answer too short	too_short
Answer too long	too_long
Irrelevant answer	irrelevant
Missing key concepts	missing_concepts
Wrong page / source cited	wrong_source
Other	other
API
POST /api/support/report-answer
{
  "book_title": "Book title or empty string",
  "page_number": null,
  "question": "Original question",
  "ai_response": "First 500 characters of the displayed answer",
  "issue_type": "incorrect",
  "description": "Optional details"
}
For parity with the answer action bar:

book_title: selected book title, or "".
page_number: first source’s page, or null.
ai_response: first 500 characters of the answer.
description: trimmed text, or null.
Successful response:

{"ok": true}
Require an issue selection, disable Submit while submitting, and show success only after the server responds. The web success panel closes automatically after 15 seconds and also provides Close.

The backend derives student identity from authentication; do not submit student name, email or user ID.

For reports inside Quiz Me, the web uses "MCQ Question" as the book title and includes the quiz question/options/correct answer/explanation as report context.

Sources: ReportIssueButton.jsx, support_router.py:125–162

9. Android/iOS requirements
Audio
Use a native player capable of MP3 and WAV.
Download authenticated audio bytes into an app-private temporary file.
Choose file extension from the response MIME type.
Do not pass an authenticated POST endpoint directly to a player expecting a public GET URL.
These playback features require no microphone permission.
Allow only one active audio feature at a time.
Handle audio interruption, headphones disconnecting and app backgrounding.
Stop/release players and temporary files on answer change, screen exit or logout.
Update UI after playback actually starts; handle player errors.
Language and text
Resolve language in this order:

Supported language on the answer response.
User’s medium_name.
Language detected from answer text.
English fallback.
Read Aloud maps language names to BCP-47 codes, for example hindi → hi-IN and telugu → te-IN.

Known mismatch: frontend utilities include Odia, but the current Explain/Quiz backend language maps omit it; Explain audio falls back to en-IN. Do not claim full Odia audio parity without separate validation.

The web strips Markdown and removes LaTeX expressions before speech/quiz generation. Consequently, spoken text may omit mathematical formulas. Preserve the displayed answer; any native improvement to formula speech should be explicit rather than silently changing the content.

Requests and state
Generate only when tapped; do not preload all audio, quizzes and decks.
Keep results associated with the answer that requested them.
Ignore late responses after switching answers or leaving the screen.
Disable duplicate submissions.
Do not blindly retry Tutor Explanation or reports after ambiguous timeouts: explanation may already have consumed quota, and a report may already have been saved.
Use the existing token-refresh/sign-in flow for 401.
Clear protected cached results on logout.
Provide accessible labels, scalable text and reduced-motion alternatives for card flips.
Support Android Back and iOS modal dismissal without leaving stale loading states.
Native acceptance checks
Verify on both platforms:

Correct button order and wrapping with large text.
MP3 and WAV playback, pause/resume/stop and interruptions.
Tutor replay without another generation request.
Dynamic quota, exhausted quota and binary-response errors.
Non-English transcript decoding.
Quiz indexing, score calculation and regeneration.
Flashcard timeout, navigation and local mastery.
Report success/failure and duplicate-tap prevention.
Answer switching during an outstanding request.
Scope for the mobile platform: implement these native controls against the existing EDUwAI backend. Do not rebuild the backend, add guessed endpoints, or modify the web app.
