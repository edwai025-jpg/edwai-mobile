Phase 2 API — Complete Specification for Mobile App
Base URL (Production): https://edwai-api-953672603784.asia-south1.run.app

All requests must include:

Authorization: Bearer {jwt_token}
Content-Type: (varies per endpoint — specified below)

Overview: How Phase 2 Works
User uploads PDF or pastes YouTube URL
        │
        ▼
Backend stores file → creates DB record → kicks off background processing
        │
        ▼
Gemini Files API ingests the PDF (or transcript text for YouTube)
        │
        ▼
Document becomes is_ready = true (poll until this is true)
        │
        ▼
User asks questions → Gemini answers using the uploaded content
        │
        ▼
Answer + page citations returned (streamed via SSE)

source_type values:

"pdf" — uploaded PDF book
"youtube" — YouTube video transcript
processing_status values:

Value	Meaning
"uploaded"	File received, processing not yet started
"processing"	Being indexed by Gemini (show spinner + progress %)
"completed"	Ready to query (is_ready = true)
"failed"	Processing failed — show error, offer delete/retry
Polling: After creating a document, poll this endpoint every 3 seconds until is_ready === true for that document ID.

Endpoint 3 — Upload a PDF
POST /api/phase2/documents/upload
Authorization: Bearer {token}
Content-Type: multipart/form-data

Form fields:

Field	Type	Required	Notes
file	File (PDF)	Yes	Must be .pdf extension. Max size from /status (default 100 MB)
title	string	Yes	Name to show in the document list
book_type	string	No	"textbook" (default), "notes", "reference", "other"
Example (React Native / Expo):

const formData = new FormData();
formData.append('file', {
  uri: fileUri,            // local file path from document picker
  name: 'my_notes.pdf',
  type: 'application/pdf',
});
formData.append('title', 'My Chemistry Notes');
formData.append('book_type', 'notes');
const response = await fetch(
  'https://edwai-api-953672603784.asia-south1.run.app/api/phase2/documents/upload',
  {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${token}` },
    body: formData,
  }
);
const data = await response.json();

Immediate Response (processing in background):

{
  "id": 42,
  "title": "My Chemistry Notes",
  "status": "processing",
  "message": "Document uploaded successfully. Processing will begin shortly."
}

On GCP production, response can also be:

{
  "id": 42,
  "title": "My Chemistry Notes",
  "status": "completed",
  "is_ready": true,

After this call: poll GET /api/phase2/documents every 3 seconds until is_ready === true for id = 42.

Error responses:

HTTP	Reason

Endpoint 4 — Add a YouTube Video
POST /api/phase2/documents/youtube
Authorization: Bearer {token}
Content-Type: application/json

Request body:

{
  "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
  "title": "Optional custom title"
}

url — Required. Accepts both youtube.com/watch?v=... and youtu.be/... formats
title — Optional. If omitted, the video's actual YouTube title is used automatically
What happens internally:

Backend extracts the transcript using youtube-transcript-api (free, no API key)
If no captions exist (or Indian language video), falls back to Gemini for transcript extraction
Duration is checked against the limit (default 60 minutes)
Transcript text is uploaded to Gemini Files API as a .txt file
Immediate Response:

{
  "id": 43,
  "title": "Photosynthesis Explained",
  "status": "processing",
  "is_ready": false,
  "source_type": "youtube",
  "transcript_source": "youtube_api",
  "word_count": 4200,
  "message": "Video transcript is being uploaded. It will be ready shortly."
}

On GCP production:

{
  "id": 43,
  "title": "Photosynthesis Explained",
  "status": "completed",
  "is_ready": true,
  "source_type": "youtube",
  "transcript_source": "youtube_api",
  "word_count": 4200,
  "message": "Video transcript processed successfully."
}

transcript_source values:

"youtube_api" — captions pulled from YouTube's own caption system (fastest)
"gemini" — Gemini AI extracted the transcript (for videos without captions)
"unknown" — fallback
After this call: poll GET /api/phase2/documents every 3 seconds until is_ready === true.

Error responses:

HTTP	Reason
400	Invalid YouTube URL / video too long / max videos reached
403	Phase 2 disabled
500	Transcript extraction failed

Endpoint 6 — Ask a Question (Streaming — Recommended)
This is the primary query endpoint. Uses Server-Sent Events (SSE) for real-time streaming.

POST /api/phase2/documents/{document_id}/query/stream
Authorization: Bearer {token}
Content-Type: application/json

Request body:

{
  "question": "What is the process of photosynthesis?",
  "mode": "retrieve"
}

mode values:

"retrieve" — Answer directly from the book/video content ("Answer from Book" / "Generate from Video")
"explain" — Explain the concept with AI understanding ("Learn Concept")
SSE Stream format:

Each event is a line starting with data: followed by a JSON object:

data: {"type": "token", "content": "Photosyn"}
data: {"type": "token", "content": "thesis is the"}
data: {"type": "token", "content": " process by which..."}
data: {"type": "done", "sources": [{"page": 12, "snippet": ""}, {"page": 15, "snippet": ""}], "citations": [12, 15], "model_used": "gemini-2.5-flash", "response_time_ms": 2340, "answer": "Full complete answer text...", "cache_used": false, "context_cached": true}

Event types:

Type	Meaning	Action
"token"	Partial answer chunk	Append content to the displayed answer
"done"	Stream complete	Show final sources, stop spinner
"error"	Something failed	Show error message from content
Reading SSE in React Native / Expo:

Use EventSource from react-native-sse or expo-sse, or use fetch with ReadableStream:

const response = await fetch(
  `https://edwai-api-953672603784.asia-south1.run.app/api/phase2/documents/${docId}/query/stream`,
  {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ question, mode: 'retrieve' }),
  }
);
const reader = response.body.getReader();
const decoder = new TextDecoder();
let answerText = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  const chunk = decoder.decode(value);
  const lines = chunk.split('\n');
  
  for (const line of lines) {
    if (!line.startsWith('data: ')) continue;
    const jsonStr = line.slice(6).trim();
    if (!jsonStr) continue;
    
    const event = JSON.parse(jsonStr);
    
    if (event.type === 'token') {
      answerText += event.content;
      setStreamingAnswer(answerText); // update UI
    } else if (event.type === 'done') {
      setSources(event.sources);      // show page citations
      setIsStreaming(false);
    } else if (event.type === 'error') {
      showError(event.content);
    }
  }
}

Usage limit (HTTP 402):

If the user has used all their questions, the endpoint returns HTTP 402 before streaming starts:

{
  "detail": {
    "upgrade_required": true,
    "questions_used": 50,
    "question_limit": 50,
    "message": "You've used all 50 questions this month. Upgrade to continue.",
    "tiers": [...]
  }
}

Show an upgrade prompt when you get HTTP 402.

Endpoint 7 — Ask a Question (Non-Streaming)
For simpler implementations that don't need streaming.

POST /api/phase2/documents/{document_id}/query
Authorization: Bearer {token}
Content-Type: application/json

Request body: Same as streaming — { "question": "...", "mode": "retrieve" }

Response (waits for full answer):

{
  "answer": "Full markdown answer text here...",
  "sources": [
    { "page": 12, "snippet": "" },
    { "page": 15, "snippet": "" }
  ],
  "citations": [12, 15],
  "model_used": "gemini-2.5-flash",
  "response_time_ms": 2340,
  "cache_used": false,
  "context_cached": true,
  "usage": {
    "questions_used": 11,
    "question_limit": 50,
    "percent_used": 22.0
  }
}

Note: answer is Markdown text. Render it with a Markdown renderer (e.g. react-native-markdown-display). Page references like [Page 12] appear in the answer text — the backend pre-bolds them to **[Page 12]**. KaTeX math ($...$ and $$...$$) may also be present for science/maths subjects.

Endpoint 8 — Query History
Returns the last 20 questions asked for a specific document.

GET /api/phase2/documents/{document_id}/query-history
Authorization: Bearer {token}

Response:

[
  {
    "id": 101,
    "question": "What is photosynthesis?",
    "mode": "retrieve",
    "answer_preview": "Photosynthesis is the process by which plants...",
    "created_at": "2025-04-28T11:00:00"
  },
  ...
]

History is stored per-document per-user, deduplicated (same question updates timestamp instead of adding a duplicate), and capped at 20 entries.

Endpoint 9 — Delete a Document
DELETE /api/phase2/documents/{document_id}
Authorization: Bearer {token}

Rules:

Cannot delete a document while processing_status === "processing" — returns HTTP 400
Cleans up: PDF from storage + Gemini Files API + all query history + DB record
Success response:

{
  "status": "deleted",
  "message": "Document and all associated data deleted successfully"
}

Partial success (file deleted but cleanup warnings):

{
  "status": "deleted_with_warnings",
  "message": "Document deleted but some cleanup operations failed",
  "warnings": ["Storage deletion: ...", "Gemini file deletion: ..."]
}

Treat deleted_with_warnings the same as success from the user's perspective.

Complete Flow Diagram for Mobile App
PDF Upload Flow
1. User picks PDF from device
2. Show upload progress bar (indeterminate)
3. POST /api/phase2/documents/upload  (multipart)
4. Get back { id, status: "processing" }
5. Show "Processing..." state for that doc card
6. Poll GET /api/phase2/documents every 3s
7. When is_ready = true → enable the document card
8. User taps the doc → navigate to Q&A screen

YouTube Video Flow
1. User pastes YouTube URL
2. POST /api/phase2/documents/youtube  (JSON)
3. Get back { id, status: "processing", word_count, transcript_source }
4. Show "Extracting transcript..." state
5. Poll GET /api/phase2/documents every 3s
6. When is_ready = true → enable the video card
7. User taps → show "Generate Notes" vs "Ask Questions" choice screen
8. Generate Notes: auto-send hardcoded notes prompt with mode="retrieve"
9. Ask Questions: show Q&A input

Querying Flow (both PDF and YouTube)
1. User types question, taps "Answer from Book"/"Generate from Video" (mode=retrieve)
   OR taps "Learn Concept" (mode=explain)
2. POST /api/phase2/documents/{id}/query/stream
3. Stream SSE tokens → show text appearing in real time
4. On "done" event → show Sources section (page numbers)
5. Save to local recent questions for quick re-ask
6. If HTTP 402 → show upgrade modal

Key Notes for Mobile Implementation
No citation images for Phase 2 — unlike Phase 1, the API only returns page numbers, not actual page images. Just display the page numbers as pills/chips.

YouTube docs never have page numbers — citations from YouTube videos are time-segment markers, not real page numbers. You may get empty sources: [] for video queries — that is normal.

Context caching — after the first query on a document, subsequent queries are faster because Gemini caches the document context for 30 minutes of inactivity. The context_cached: true flag in the response indicates this is active.

Email notification — when a document finishes processing, the user receives an email if they have one. The mobile app should still poll actively rather than relying on the email.

Max limits (from /api/phase2/status): 20 PDFs and 20 YouTube videos per user by default. Check these limits and show a friendly message when the user hits them.
